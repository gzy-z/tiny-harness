# Day 13 学习日报

日期：2026-10-13

## 我今天学会了
1. **控制反转（on_event 回调）**：`run_loop` 加 `on_event=None` 参数，默认回调还是 print——引擎不再决定"输出到哪"，只负责"发生了什么"。REPL 一行不改，Web 端把回调接成 SSE。**引擎管发生，调用方管去向**
2. **向后兼容的三层验收法**：①静态比对（把 emit 在脑子里展开，和原 print 逐字对，盯 indent 和文本）②动态冒烟（起 REPL 跑一个必触发工具的任务，核对引擎事件行原样）③自动哨兵（诚实地说：pytest 只护逻辑，**print 格式不在哨兵管辖**——想让这层自动护叫快照测试，今天知道名字就行）。知道测试的边界和写测试一样重要
3. **SSE（Server-Sent Events）**：`data: {json}\n\n` 报文 + `text/event-stream`——服务器→浏览器单向流，比 WebSocket 轻，聊天够用。前端 EventSource 只支持 GET，POST 得 fetch + ReadableStream 手动读
4. **半包问题**：网络会把一条消息切两半送达，`buf.split("\n\n")` 后 `parts.pop()` 把不完整的尾巴留到下一轮拼——和 Day 3 在 llm.py 攒流式碎片是同款活
5. **线程 + 队列中转（生产者-消费者）**：run_loop 同步阻塞几十秒，HTTP 要边跑边吐——worker 线程跑引擎塞 queue，生成器从 queue 取着 yield
6. **每条流都要有葬礼**：`finally: q.put(None)` 结束哨兵——线程崩了流也得关，不然浏览器转到天荒地老
7. **悬空复读 bug（今日主角）**：run_loop 收工时最终回答 return 了但没 append 进 messages——历史变成 `...tool结果 → user2`（工具结果后没人说话，协议悬空）→ 模型先把上轮欠的总结补出来再答新题 = 复读。潜伏已久的病，Web 连续追问把它炸出来。修法一行：引擎统一 `messages.append(msg)`。副产品红利：历史干净后模型**不复读也不傻干**（第二问没再调 now，直接复用上轮时间）
8. **共享引擎的契约要写进 docstring**：谁管哪部分历史，以前是隐式约定，今天用 bug 付了账单
