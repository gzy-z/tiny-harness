## 我今天学会了
1. **评测三件套**：任务集 + 裁判 + 跑批统计。compare_edit.py 只有半件（一个任务、零裁判）——它只数 token 不查对错，**把"便宜"当"对"**，空响应能拿全场冠军
2. **方差是评测的第一敌人**：同一考题七连跑 33→44→44→10→**-30**→6→**58**，摆幅 88 个百分点，连方向都能翻——单次 A/B = 抽签，写进 README 会被复现打脸
3. **成功率和成本是两个维度**：`return p_total + c_total + ok` 把布尔加进 token，失败反而"便宜 1 分"——营养不良冠军陷阱的回马枪
4. **黑匣子验尸 → 冤案**：read_answer 2/3 失败，开箱发现模型无罪——是考题把文件指错了（FALLBACKS 在 llm.py 不在 check_key.py）。更阴的：模型不看文件幻觉答"2"反而 pass——**这道题奖励幻觉、惩罚诚实**。评测三类错误源：模型错 / 裁判错 / 出题人错
5. **考题守则**：先验靶再出题，靶钉在稳定材料上（llm.py 是活代码会进化，check_key.py 的 docstring 才是稳靶）
6. **import 副作用**：模块顶层裸代码会在被人 import 时偷跑——compare_edit 底部没穿 `if __name__ == "__main__"` 装甲，每次跑 eval 都白烧 2 次 API 还冒充实验结果
7. **没输出 ≠ 跑了**：入口段缩进进 main 体内 → main 永远不被调用 → eval.py 静默罢工
8. **故障注入（chaos 入门）**：不等中转站发病，自己当瘟神——30% 概率抛节点病异常。关键设计：**病毒必须注射进防线内部（try 块里）**，在 call_llm 门口抛，重试根本接不住
9. **吞异常不留遗言 = 调试黑洞**：except 里硬编码 0 把线索全吞了；`except Exception as e` 至少 print 出击穿原因
10. **透传惯用法**：`**llm_kw` 让 run_task 不关心配置细节、原样转交 call_llm——中间层不改就能加新参数
